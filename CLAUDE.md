## Hard rules (from atrium-docs — violating these means the session is wrong)

- **Tenant isolation everywhere.** Every query/endpoint company-scoped. Cross-tenant access must be impossible. Enforced twice since M3.2: application-level scoping (every repo method takes a companyId) AND Postgres RLS (`app.company_id`/`app.bypass_rls` GUCs, 08 §Security rule 6) — any new repository call needs a real `@Transactional` boundary somewhere in its call chain, or RLS silently returns zero rows instead of the correctly-scoped ones.
- **Claiming:** Postgres `FOR UPDATE SKIP LOCKED` + lease. Idempotency keys (`taskId:attempt`) — a redelivered task never double-bills an LLM call.
- **Append-only audit:** every task state change = `task_events` row in the same transaction.
- **Nothing ships unreviewed:** `pending_review` is a hard gate.
- **Roles are data:** new capability = registry row + queue. `if (skill == …)` in routing is a bug by definition.
- **Secrets never meet prompts:** PromptAssembler sees only role definition + task + feedback.
- **Team view is pure derivation:** `shared/selectors.ts` (`liveTeamZones`) over `state.agents`/`state.tasks` only — no team-only store actions, endpoints, or state. (Replaced the two former office rules when the SkyOffice track was retired, 2026-07-15.)
