# web-dashboard

**What:** React dashboard in `web/` — the non-game UI. Mid-redesign from "office-canvas-front-and-center with overlay panels" into a Linear/Notion/Datadog-style "AI Operating System" per the approved plan at `/Users/geetanshagrawal/.claude/plans/multi-agent-employee-platform-redesign-fluttering-crescent.md` (MF-1…MF-6, one milestone per session, run via `/milestone`). SkyOffice remains fully functional throughout — it's demoted to one optional page (`/office`), never removed, never the only place a feature lives.

**State (2026-07-14, MF-2): primitives + real Mission Control live.** `shared/types.ts` gained `TaskEvent` + `Task.events: TaskEvent[]` — the one real contract extension, threaded through `adapters.ts`/`queries.ts` (API mode, zero extra requests — `useEnrichedTasks` already fetched `/tasks/{id}/events`) and `mockStore.tsx`/`mocks/tasks.json` (mock mode) together. New `shared/selectors.ts` — pure derivations (`computeKpis`, `companyBudgetBurn`, `companyPulse`, `liveMissionTask`, `synthesizeFeed`, plus `kanbanColumns`/`orgTree` for MF-3/MF-4) with no dependency on `storeTypes.ts`, safe to import from any page. `ui/` grew nine primitives: `PageShell`, `Card`, `StatCard`, `Tabs` (`?tab=`-synced), `StatusPill`, `EmptyState`, `Timeline`, `Feed`, `DataTable`, `Graph` (hand-rolled SVG layered tree, node status via new `--node-*`/`--glow-running` CSS vars). `pages/mission/MissionControlPage.tsx` rewritten from a teaser placeholder into the real home page: Company Pulse, KPI row, Live Mission hero, Workflow Preview (mini `Graph`), Output Preview, Agent Status grid, Budget Burn bar (80% warning), Live Activity feed. New `index.css`/`theme.ts` tokens are additive only (`--status-blocked`, `--node-*`, `--surface-{1,2,3}`) per the office's `--status-*`-by-name boot read.

**State (2026-07-14, MF-1): router + new shell live.** `react-router@7.18.1` added (library mode, no loaders). `App.tsx` → `BrowserRouter` → `shell/AppShell.tsx` (replaces `dashboard/DashboardLayout.tsx`, deleted along with `Sidebar/TopBar/RightRail/BotBar.tsx`). 11 real routes (`/`, `/tasks`, `/workflow`, `/employees`, `/organization`, `/projects`, `/knowledge`, `/reports`, `/office`, `/notifications`, `/settings`, `*`→`/`) — most are still thin `pages/PagePlaceholder.tsx` wrappers with an "Open classic X" button into the still-live legacy panel; `/office` and `/employees` are real. Every pre-MF-1 panel (Workspace/Chat/Analytics/Announcements/Approvals/Payroll/Task Flow/Profile/Focus) stays reachable via a temporary "Classic Panels" section in `shell/NavSidebar.tsx` + `shell/LegacyPanelHost.tsx` (the old `DashboardLayout` `PANELS` map, now a bridge deleted panel-by-panel as MF-2…MF-6 build real replacements). New `ui/` primitives: `Drawer.tsx` (right-edge slide-over, first real use: `ChatPanel.tsx` rehomed onto it, reachable from a persistent header icon) and `Toast.tsx` (replaces BotBar's notice banner). New `shared/nav.ts` (`useAppNav()`) is the one indirection between components and `openPanel` dispatches — later milestones swap its three functions to real navigation without touching call sites. `storeTypes.ts`/`AppState`/`Action` **untouched** — deliberate, keeps this milestone low-risk.

**Real bug found + fixed this session:** moving panels out of the office-scoped `.dashboard-office` container to a shell-level sibling made `PanelShell`'s `.panel-overlay` (`position:absolute;inset:0`) resolve against the *viewport* instead of a bounded region — silently swallowing clicks on the nav sidebar/header any time a legacy panel was open. Fixed by mounting `LegacyPanelHost` inside `.app-shell-content` (already `position:relative`) instead of at the shell root, and changing `Drawer.css`'s overlay from `position:fixed` to `position:absolute` to match. Verified fixed: can now switch between classic panels directly via the sidebar without closing the open one first.

**`OfficeCanvas.tsx` — two surgical fixes, zero behavior change otherwise:** (1) the `onAgentClicked → dispatch(openPanel profile)` effect moved out to new `pages/office/OfficePage.tsx` — canvas is now presentation-only; (2) the old `firstRoomRender` skip-first-render hack (silently dropped a non-default room on remount) replaced by reading the current room from a ref at `GAME_READY` time — `scenes/Game.ts` subscribes to `FOCUS_ROOM` before emitting `GAME_READY` in its own `create()`, so this always lands on a live listener, including right after a fresh mount on a non-Lobby room.

**Verified in browser, both `VITE_USE_MOCKS` modes:** all 11 routes deep-link correctly (survive hard refresh); `/office` renders the real roster, room chips update state and the camera pans (confirmed real, though visually slow in this specific automated-browser tab — `document.hidden===true` there, the same "Phaser's loop freezes in hidden tabs" caveat noted since session 3, not a regression); avatar click → real Agent Profile panel (confirmed via a direct `pointerup` emit on the sprite — coordinate-based clicking is unreliable for canvas hit-testing in this harness); Employees page card click → same panel; New Task / Hire Agent / Chat work from the header; every Classic Panel opens and correctly switches to another via the sidebar post-fix (Payroll showed real budget numbers matching session 6i exactly). `make check` clean (only the 7 pre-existing fast-refresh warnings, zero new ones).
