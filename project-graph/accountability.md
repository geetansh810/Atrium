# accountability

**What:** [[core-api]] module owning budgets ("payroll"), approvals, the append-only `task_events` audit log, usage metering, and analytics rollups.

**State: + analytics rollups + StatsRollupWorker/AnalyticsService LIVE (M2.3, 2026-07-15 session 22).** New `agent_stats_daily` table (`V6__agent_stats_daily.sql`) — deviates from 03's original sketch by adding a `skill` column to the primary key (`company_id, agent_id, skill, day`) + `cost_micro_usd`, a docs-first amendment so `top-skills` needs zero cross-module reads into [[routing]]'s `tasks` table. New `StatsRollupWorker extends eventbus.EventCursorWorker` — the SECOND real durable-consumer subclass after [[agentmind]]'s `LearningPipeline` — consumes `task.completed|approved|rejected` from the outbox, reading ONLY the payload's `agentId`/`requiredSkill`/`attempt` fields (three small additive fields `routing.TaskService` now puts on those three event types) — never a `Task` entity or `TaskRepository`, keeping the documented one-way `routing → accountability` dependency intact even for a feature that conceptually "belongs" to task lifecycle. New nightly `StatsRollupReconciliationJob` (advisory-lock singleton, same idiom as `OutboxRetentionJob`/`MemoryTtlArchiver`) — a genuine drift-correcting full recompute of the trailing 2 UTC days straight from `outbox_events` (never purged ahead of any consumer's cursor), the actual "nightly" half of 03's "analytics rollup (nightly + on-approve)" schema comment. New `AnalyticsRepository`/`AnalyticsService`/`AnalyticsController` — 5 endpoints (`summary`/`tasks-7d`/`agent-performance`/`top-skills` per 04, plus a **new `cost-per-task`** not in the original 17 sketch, added docs-first since the Budget Ledger's per-task cost table needs real per-task granularity `agent_stats_daily`'s per-day/skill grain can't give — it queries `usage_records` directly instead). All raw-JDBC aggregate reads, no Hibernate mapping, matching `PgVectorMemoryStore`'s established idiom. **Done-when verified live against the real Agrawal Namkeen tenant**, not just the 10 new tests (141/141 green): created a real task, watched Priya's real Gemini call complete+get approved, and confirmed all 5 endpoints reflected it within one poll tick — see [[milestones]] for the full story.

**Earlier — shared usage-ledger (M-LN1, 2026-07-15 session 16).** New `UsageLedger` interface + `UsageLedgerService` impl — the `usage_records` insert-once-then-`recordSpend` logic that used to live inline inside `execution.UsageRecorder` moved here, since [[agentmind]]'s new `LearningPipeline` needs the identical dup-guard behavior for its own `learn:{eventId}`-keyed extraction calls, and `agentmind` may depend on `accountability` but never on `execution` (12 §2 — boundary rule added this session). `execution.UsageRecorder` now just computes the `taskId:attempt` key and delegates here; its own behavior/tests are unchanged. See [[agentmind]] for the full M-LN1 story.

**Earlier — BUDGET ENFORCEMENT LIVE (M0.7, 2026-07-13 session 6f).** `BudgetService implements BudgetGuard, BudgetLedger` replaces `NoopBudgetGuard` (deleted). New `accountability/domain/Budget` entity (03/15's `budgets` table + new `alerted_at TIMESTAMPTZ` column, `V3__budget_alerted_at.sql`) + `BudgetRepository`. `canSpend(companyId, agentId)` — consulted inside [[routing]]'s claim tx exactly as before — checks BOTH the agent's own cap and the company-wide cap (`agent_id IS NULL` row) for the current period (`YearMonth.now(clock)`); a missing row for either scope means that scope is uncapped (budgets are opt-in). **Design call:** an agent-scope breach auto-pauses that agent (`AgentDirectory.pauseForBudget`, new interface method) via [[registry]]'s existing `AgentLifecycleService.stop`; a company-wide breach refuses the claim WITHOUT pausing any single agent, since the cap is shared and picking one to punish would be arbitrary. **Real bug caught by the tests, not by inspection:** the auto-pause + `budget.exceeded` outbox write can't happen inside `canSpend`'s own transaction, because `PostgresWorkBroker.claim` immediately throws `ConflictException` right after `canSpend()` returns false to produce the 409 — and that throw rolls back the WHOLE transaction, silently undoing the pause and the event. Fixed by extracting both into new `BudgetBreachRecorder` (`@Transactional(propagation = REQUIRES_NEW)`), which commits independently of whatever the caller's claim transaction does next. `UsageRecorder.record` (execution) now calls `BudgetLedger.recordSpend` — but ONLY when the idempotent insert actually wrote a new row, so a deduped redelivery never double-counts spend even though `usage_records` itself already guards the double-bill case. `recordSpend` increments both scopes' `spent_tokens` and, crossing `alert_pct` (default 80) for the first time this period (`alerted_at IS NULL`), emits `budget.threshold` once — the natural `(company_id, agent_id, period)` UNIQUE key means a new period gets a new row and the dedupe resets for free. **Circular-dependency gotcha:** wiring `pauseForBudget` into `JpaAgentDirectory` needed `AgentLifecycleService` — but that sits behind `RuntimeRegistry → LlmLoopRuntime → WorkBroker → AgentDirectory`, an eager cycle at context startup; fixed with `@Lazy` on that one constructor parameter. New `accountability/api/BudgetController` — `GET/PUT /companies/{id}/budget`. `StatsRollup` still not started (M2.3).

**Rev C additions ([[agent-platform]]):** budget tiers per Paperclip — `budgets.alert_pct` soft alert (`budget.threshold` event, once per period) + hard cap now **auto-pauses** the agent (`agents.paused`) besides refusing claims — DONE at M0.7 above; usage idempotency namespaces widen to `taskId:attempt` / `learn:` / `embed:` (learning + embeddings are metered payroll too, still pending); StatsRollup is a durable outbox consumer — DONE at M2.3 above.

**Key components:**
- `BudgetGuard.canSpend(companyId, agentId)` / `BudgetLedger.recordSpend(companyId, agentId, tokens)` — both implemented by `BudgetService` (accountability). Real cap check + over-cap → claim refused + `budget.exceeded` outbox event + auto-pause is DONE (M0.7) — see State above for why "flag the task" (17's literal wording) was deliberately NOT implemented as a `task_events` row: `queued→flagged` isn't a legal `TaskStateGuard` edge, and flagging a shared queue item would wrongly block OTHER agents from claiming it over one agent's budget.
- `UsageRecorder.record()` — lives in [[execution]], not here (M0.5b design call — it's called directly from `LlmLoopRuntime`, same tx as `TaskService.complete()`); calls `BudgetLedger.recordSpend` as of M0.7.
- `StatsRollupWorker`/`StatsRollupReconciliationJob`/`AnalyticsService` — updates `agent_stats_daily` on approve/reject/complete (durable consumer) + nightly (full recompute). Success rate = approved ÷ (approved+rejected). DONE — M2.3.

**Hard rules:** `task_events` is append-only — never UPDATE/DELETE. `pending_review` is a hard gate; nothing ships unreviewed.
