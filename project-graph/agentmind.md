# agentmind

**What:** [[core-api]] module owning the skills registry (14 §1) — the first slice of the "depth" subsystem ([[agent-platform]]: skills → memory → knowledge → learning). Future milestones (M-CTX1/M-MEM1/M-KN1/M-LN1) add ContextAssembler, MemoryStore, knowledge ingestion, and the learning pipeline into this same module.

**State: SKILLS LIVE (M-SK1, 2026-07-14 session 13).** Schema was already live since M0.1 — `V2__agent_platform.sql` pasted the full 15 §§2–4 Rev C schema verbatim (skills/memories/knowledge tables all created then), so this milestone is Java/API only, no new DDL. `domain/`: `Skill` (versioned, `company_id NULL` = global platform skill, `UNIQUE(company_id, key, version)` — same versioning idiom as `RoleDefinition`), `RoleDefinitionSkill`/`AgentSkill` (composite-key join entities via `@IdClass`, first use of that pattern in the codebase). `SkillService`: CRUD + versioning (new version = new row, latest-per-`(company_id,key)` dedupe done in Java over an ordered query rather than JPQL window functions), attach/detach to agent, attach to role, and the `/mind` view assembly (memory/knowledge parts zeroed until M-MEM1/M-KN1). New `V5__seed_platform_skills.sql`: 2 platform skills per seeded template (coder: code-review-checklist + unified-diff-output; tester: test-coverage-checklist + bug-report-contract; research: source-ranking-procedure + summarization-contract), attached to their global `role_definitions` rows.

**Boundary decision — hire-time auto-attach without breaking the one-directional `agentmind → registry` dependency (12 §2):** `AgentService.hire()` (registry) needs to trigger a skill attach, but registry may not import agentmind types. Solved with a hook interface **owned by registry**: `registry.RoleSkillAttachment` (one method, `attachTemplateSkills`), implemented by agentmind's `SkillAttachmentService`. This keeps the only static import direction as `agentmind → registry` (agentmind implements a registry-owned interface) — same shape as `AgentDirectory`/`BudgetGuard`/`RoleDefinitionLookup`, just inverted: here the *consumer* (registry) owns the interface and the *provider* (agentmind) implements it, because the call originates in registry's hire flow. `RoleDefinitionLookup` gained a company-scoped `findVisibleToCompany` (agentmind needs it to validate the `/role-definitions/{id}/skills` attach endpoint's tenant ownership; the pre-existing `findById` had no company param since its only prior caller — PromptAssembler — already holds a trusted row).

**Design call — role-skill attach restricted to company-owned role definitions:** 16 §2's literal text doesn't restrict `POST /role-definitions/{id}/skills` to non-global role definitions, but role templates (`company_id NULL`) are ONE shared row every tenant hires from — attaching from company A's request would leak that skill into every other company's future hires from that template. `SkillService.attachToRole` requires `roleDefinition.companyId == companyId`, 404s on a global template id. Test: `attachToRoleOnlyAffectsCompanyOwnedRoleDefinition`.

**Key rules:** only `platform`/`company` trust-level skills may ever reach a prompt (`agent_proposed` is inert until a human promotes it — not built yet, no promotion path exists until M-LN1). Skills are versioned; attachments pin a specific version id, so a role's skill upgrade is an explicit re-attach, never automatic. `agent_skills.source`: `hired` (auto, from template) / `assigned` (manual attach) / `learned` (not produced yet — M-LN1).

**Done-when verified:** hire from `coder`/`research` templates → `/agents/{id}/mind` shows exactly the template's skills with `source:"hired"`; attach a custom company skill → appears with `source:"assigned"` + given proficiency, detach removes it, hired skills untouched; two companies each see all 6 global skills + only their own custom skill in `GET /companies/{id}/skills`, `kind` filter works, versioning shows latest-only with correct dedup, cross-company version-attempt 404s. 82/82 core-api tests green (2 skipped, live-key tests unchanged). `make check` clean.
